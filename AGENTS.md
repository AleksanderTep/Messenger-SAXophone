# Инструкции для работы с Messenger SAXophone

Перед коммитом прочитать docs/git-workflow.md и docs/team.md.

- Не пушить напрямую в main или develop; работать в отдельной ветке задачи.
- Указывать S1-xx/S2-xx/S3-xx в ветке, сообщении коммита и PR.
- Добавлять в index только явный список файлов задачи. Не использовать git add . или git add -A.
- Перед коммитом проверить staged diff, список файлов и отсутствие секретов.
- Использовать имя и email конкретного автора только по явному указанию руководителя;
  роли сами по себе не доказывают авторство. Не применять глобальную Git-личность автоматически.
- Не менять даты автора/коммиттера и не подделывать review, CI или историю участия.
- Для существующих подготовленных изменений пользоваться commit-plan.json;
  порядок определяется зависимостями. Не создавать пустые коммиты ради активности.
- Перед push выполнять проверки, относящиеся к изменению. При ошибках исправлять причину.
- Не делать force push, не переписывать опубликованные коммиты и не менять main на старую историю.
- PR направлять в develop. Для зависимой серии допустимы draft PR с base предыдущей веткой;
  после слияния зависимости перевести base в develop. Зависимые PR не сливать раньше основания.
- Слияние требует реального review другого участника и успешных доступных проверок.
  Отсутствие workflow не считать успешным CI. Автоматически одобрять PR от чужого лица запрещено.
- Не закрывать карточку Pyrus только по факту push: сначала проверить все критерии.
- Публикация подготовленных изменений по расписанию: не более одной группы за запуск,
  без изменения дат и без массовой отправки пропущенных запусков. Сохранять локальный журнал.
- Прогресс текущего приложения и чужие незакоммиченные файлы сохранять.
