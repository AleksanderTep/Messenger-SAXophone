# Памятка по Git и npm

Ответственный Вячеслав Силантьев. Git хранит историю; commit фиксирует локальное изменение; push публикует ветку; PR предлагает слияние. Автор PR определяется вошедшим аккаунтом. Review выполняет реальный проверяющий.

- Проверить git status и git branch --show-current; не сбрасывать чужую работу.
- От актуального develop создать ветку задачи. В sprint/* находится документация, не приложение.
- Изменить согласованный участок. Проверить git diff, добавить явные файлы через git add -- путь, затем git diff --cached.
- Создать понятный commit с номером задачи, проверить git show, опубликовать ветку.
- Открыть PR в develop с проверками; другой участник читает diff. После исправлений и CI принимается решение о merge.

Node.js запускает инструменты разработки, браузер — интерфейс. npm управляет зависимостями и командами package.json. В frontend приложения npm ci устанавливает версии из lock-файла; npm run dev — Vite; npm run lint — проверка; npm test — unit; npm run build — сборка; npm run test:e2e — браузерные сценарии. Полный auth E2E требует работающий API и E2E_API=1.

node_modules, dist, .env и ключи не коммитят. Missing package.json в sprint/* означает, что открыта ветка материалов; использовать отдельный чистый checkout приложения.
