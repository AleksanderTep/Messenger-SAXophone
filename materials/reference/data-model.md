# Данные и границы схемы

Ответственный Николай Седов. users: UUID, username, email, display_name, password_hash, даты. username/email уникальны, включая lower-индексы; хеш не выдаётся API.

auth_sessions: id, user_id, expires_at. Пользователь имеет несколько независимых сессий. JWT jti совпадает с id, sub — с user_id. Logout удаляет текущую запись, не все сессии пользователя.

chats: уникальная упорядоченная пара пользователей. chat_members: связь чата и участника. messages: ссылка на пару (chat_id, sender_id), ограничение длины текста, индекс истории. Это задел схемы: API создания чата, отправки и чтения сообщений нет.

ORM-модель описывает таблицы в Python, миграция меняет реальную схему. PK идентифицирует запись, FK защищает связь, транзакция объединяет изменения. Предварительный поиск дубликата удобен, но параллельные регистрации окончательно разрешает индекс БД. Миграционный downgrade допустим только на одноразовой БД.
